## v0.5.1 — Real lunar libration and phase / 真实月球天平动与月相

v0.5.1 improves professional desktop presentation: a single-line application heading and Moon-specific data/lighting disclosure based on the actual runtime mode.

Celestial Atlas now uses **official NASA NAIF CSPICE N0067** with **DE442s SPK** and the high-precision **DE440 lunar binary PCK / Moon ME frame kernel** in its opt-in precision build. Earth and Moon observed imagery comes from NASA's original sources; the images are **not generated by AI**.

### Implemented / 已实现

- C++20, Qt6 Widgets, OpenGL 3.3 desktop application.
- Two **independent globe viewing scenes**: Earth with NASA Blue Marble; Moon with NASA LROC WAC 2025 observed global color mosaic. Download/cache separately and preserve provenance + SHA-256.
- **New in v0.5:** In the CSPICE-enabled build with valid kernels, the Moon Survey camera follows the computed **geocentric sub-Earth direction** in the Moon's **MOON_ME** body-fixed frame, exposing physical lunar libration. Mouse dragging temporarily releases camera following; reset restores it.
- **New in v0.5:** The Moon's shader receives the computed Moon→Sun direction in that same body-fixed frame, enabling a geometrically correct **illuminated lunar phase** rather than a fixed presentation lamp.
- Explicit UTC date control, pause, time scaling, orbit-camera drag and zoom, numerical Moon phase/distance/geometry, and screenshots exported by the **actual OpenGL application** with data provenance.
- Tests: synthetic Moon geometry and Sun/Earth coordinates; official NASA kernel tests for new/full Moon epochs, normalized MOON_ME vectors, changing libration, and agreement between numerical lunar illumination and rendered lunar light direction.
- Windows portable archive built through GitHub Actions via official Qt `windeployqt`.

**Critical build distinction:** The Windows portable binary currently has no CSPICE linked, so the Moon is a **real survey-textured globe with visibly labeled fixed studio light**, *not* a physically accurate Moon phase. Linux CI compiles the real NASA CSPICE libraries and uses the official NAIF SPK/PCK/FK to demonstrate the correct dynamic behavior. Missing kernels never produce invented data.

### Build / 构建

General C++ core without Qt6/CSPICE:

```bash
cmake -S . -B build-core -DATLAS_BUILD_GUI=OFF
cmake --build build-core --parallel
ctest --test-dir build-core --output-on-failure
```

To enable real lunar orientation on Linux, download official NAIF N0067 C toolkit and kernels. See [precise, reproducible CSPICE instructions](docs/SPICE-INTEGRATION.md).

### Scientific limitations / 科学真实性说明

- **Lunar frame:** DE440 MOON_ME lunar orientation; **lunar/solar position:** DE442s. This uses geometric positions with `NONE` corrections (no light-time, stellar aberration or local observer parallax). Thus it represents **geocentric** lunar phase/libration, not a topocentric telescope observation.
- The NASA 2025 LROC map is a *processed observed* composite adapted for 3D visualization, with LOLA albedo data supplementing high-latitude gaps, not a raw scientific exposure.
- Moon geometry is rendered as a sphere. Real DEM displacement / relief, true spatial scale, shared Earth–Moon orbit view, lunar eclipses, precise Earth ITRF/EOP orientation, Gaia stars and interstellar navigation are **not yet implemented**.
- Missing SPICE kernels or unsupported Windows CSPICE builds fall back to an explicitly labeled **survey/studio view**. Scientific geometry is never fabricated.
